# Аналитика чата

`GET /chats/:id/analytics?company_id=1` возвращает статистику всей сохранённой истории чата. Компания проверяется так же, как при чтении сообщений. Текущий API ещё не использует авторизацию: `company_id` — фильтр, а не доказательство прав доступа.

```powershell
Invoke-RestMethod 'http://localhost:8080/chats/1/analytics?company_id=1'
```

- `total_messages`, `messages_in`, `messages_out`: количество сообщений.
- `media_messages`: сообщения с непустым полем `media_type`.
- `response_count`: число отвеченных серий входящих сообщений.
- `avg_response_seconds`, `max_response_seconds`: среднее и максимальное время от первого входящего сообщения серии до первого исходящего ответа. Последующие исходящие не создают дополнительные ответы. При отсутствии ответов — `null`, при мгновенном ответе — `0`.
- `unanswered_messages`, `awaiting_reply_since`: количество последних входящих без ответа и время самого раннего из них. После ответа — `0` и `null`.
- `first_message_at`, `last_message_at`: границы истории, `null` для пустого чата.
- `daily_activity`: входящие и исходящие по дням UTC; только дни с сообщениями, по возрастанию. Пустая история — `[]`.

Ошибка формата ID/компании — `400`, отсутствующий или чужой чат — `404`, ошибка хранилища — `500`, отсутствие подключённого usecase сообщений — `503`.

Время ответа считается в календарных секундах, без рабочего расписания. Расчёт читает историю страницами по 200 сообщений; порядок — `sent_at, id`. Ответ включает только сообщения в БД, без обращения к Telegram. Это оперативная статистика: при одновременном импорте истории между страницами результат может меняться; для отчётов с фиксированным срезом потребуется транзакционный снимок. AI-анализ текста в этот API не входит.
