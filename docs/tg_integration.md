Сейчас клиент в internal/telegram/client.go умеет только получать первую страницу диалогов в методе Inspect, хранит сессию в локальном файле и никак не связан с основным сервером.

Нужно реализовать полноценное чтение диалогов и истории сообщений с подключённого Telegram-аккаунта и сохранение их в PostgreSQL:

В internal/config/config.go добавь конфигурацию для Telegram MTProto (TELEGRAM_API_ID, TELEGRAM_API_HASH, при необходимости базовый путь для сессий или ключ шифрования сессий в БД) с проверкой обязательных параметров при включённой синхронизации.

В internal/telegram/ раздели транспорт и бизнес-логику: реализуй хранение сессии из accounts.session (реализация интерфейса хранилища сессий gotd поверх поля Session в БД или безопасный адаптер) либо явную связку с AccountRepository, чтобы каждый аккаунт из таблицы accounts мог поднимать своё подключение без привязки к интерактивному терминалу.

Реализуй в internal/telegram/ сервис чтения диалогов и сообщений по конкретному аккаунту:

Получение списка личных диалогов (PeerUser — приоритетно для корпоративного контроля переписок, с возможностью фильтрации каналов и ботов) через пагинацию MessagesGetDialogs с использованием OffsetDate, OffsetID и OffsetPeer, а не только первой страницы.

Чтение истории сообщений по каждому диалогу через MessagesGetHistory с ограничением батча и инкрементальной догрузкой (только новые сообщения после последнего сохранённого telegram_message_id, чтобы не выкачивать весь чат каждый раз и не ловить флуд-лимиты Telegram).

Определение направления сообщения (in или out по признаку исходящего сообщения в MTProto), извлечение текста, даты отправки (SentAt) и типа вложения (photo, document, voice в MediaType без скачивания самих файлов).

Реализуй в internal/usecase/ сервис синхронизации (например, SyncUsecase), который:

Создаёт или находит собеседника в ContactRepository по company_id и telegram_user_id.

Создаёт или обновляет диалог в ChatRepository (актуализирует last_message_at, unread_count и awaiting_reply_since с учётом направления последнего сообщения).

Сохраняет сообщения через MessageRepository.Create (используя существующую защиту от дубликатов по (chat_id, telegram_message_id) в internal/storage/postgres/message.go) и обновляет last_activity_at и статус аккаунта.

Обрабатывает ошибки MTProto (например, FLOOD_WAIT с паузой, отозванную сессию переводом аккаунта в disconnected или banned).

Добавь фоновый воркер периодической синхронизации активных аккаунтов (с управляемым контекстом и graceful shutdown в cmd/app/main.go) и HTTP-эндпоинт для ручного запуска синхронизации конкретного аккаунта (например, POST /accounts/:id/sync), чтобы процесс можно было тестировать и отлаживать через API.
