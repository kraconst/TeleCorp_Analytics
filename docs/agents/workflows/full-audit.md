# Workflow: full-audit

Вход: цель аудита — working tree, branch/PR с базой или заданный объём чистого `main`. Аудит только читает и проверяет; автоматические исправления запрещены. Применяются [AGENTS.md](../../../AGENTS.md), [protocol](../protocol.md) и role-файлы.

## Запуск

1. Зафиксируйте цель, base commit/diff, `git status`, требования к окружению и исходный список файлов. Для working tree включайте существующие изменения только с ведома пользователя.
2. Если нужен контекст, вызовите Researcher в read-only режиме для поиска фактических паттернов. Не выполняйте feature-декомпозицию и не вызывайте Coder.
3. Передайте Reviewer цель, RFC/требования либо явный audit scope, diff, файлы и Research. Reviewer загружает `code-auditor` и возвращает findings с доказательствами, severity и pre-existing-статусом.
4. Передайте Tester ту же неизменённую базу/diff и результаты Reviewer. Tester загружает `go-test-runner`, выполняет применимые проверки и возвращает команды, exit codes, PASS/FAIL/SKIPPED.
5. Повторно проверьте `git status` и diff: аудит не должен изменить исследуемые файлы. Любое изменение зафиксируйте как нарушение, не скрывайте и не откатывайте чужие данные.
6. Сведите отчёт: scope/база, findings Reviewer, отдельные результаты Tester, pre-existing failures, пропущенные проверки, риски и read-only post-check.

Для повторного аудита чистого `main` diff может отсутствовать: явно укажите проверяемые пути/пакеты. Reviewer анализирует заданный объём, Tester — текущее состояние; не описывайте это как аудит несуществующего PR.

Статус результата не означает разрешение на исправление. После аудита человек решает, создавать ли отдельный RFC и feature-pipeline.
